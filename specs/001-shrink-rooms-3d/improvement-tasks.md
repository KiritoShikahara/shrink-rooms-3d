# グラフィックス・UI・UX 改善タスク(100件)

**対象**: Shrink Rooms 3D(`specs/001-shrink-rooms-3d/`)の完成後の磨き込み
**使った観点**: `game-design-sakurai`(桜井政博「ゲーム作るには」)と `game-design-masters`(品質と UI/UX、Hodent、Swink、Celeste など)
**作成日**: 2026-11-10

## 読み方

- ID は `G-01` のように「カテゴリー記号-連番」です。
- **優先**: P1 = 先にやる(印象と操作性が大きく変わる)、P2 = 次、P3 = 余裕があれば。
- **目安**: 作業時間の見積もりです(分)。自分で書いたノードの修正を含み、確認の時間は含みません。
- **根拠**の記号:
  - S = 桜井(例 `S-F01` = グラフィック1、`S-G01` = モーション1、`S-H01` = エフェクト1、`S-I01` = サウンド1、`S-J01` = UI1、`S-D01` = 仕様1)
  - M = masters「品質と UI/UX」(例 `M-手触り4` = 手触りの4番、`M-UI6` = UI/UX の6番)
- **制約**: 提出サイズ 2GB 以下(現在 約2.5MB)、標準プラグインのみ、エンジンの Editor 専用コンテンツ(`/Engine/VREditor`、`/Engine/EditorSounds`)に新しく依存しない。

## 現状の弱点(タスクの出発点)

1. 移動、押す、収縮がすべて瞬間移動で、手応えがない(`SnapToGrid`、`UpdateWalls`)。
2. 見た目が単色の立方体で、シルエットと明暗が弱い。影が真っ黒で、壁の枠が太く暗い。
3. 効果音は仮(エンジンの VR エディタ用)。BGM と環境音がない。
4. UI は英語の白文字と灰色ボタンのみ。フェード、操作説明、設定がない。
5. 失敗の原因(どの壁に潰されたか)と、次の収縮の予告が分からない。

## 進め方(マイルストーン)

1. **M1: 手触りと見た目の土台(P1 の A、B、C、D)** — 動かしたときに気持ちいいことを最初に確認する。完了基準: 移動、押す、収縮、潰れる、が補間と音と演出で揃い、ステージ1 の 15 秒動画を撮って印象が良い。
2. **M2: 読みやすさ(P1 の E、G、H、J)** — 情報が読めること。完了基準: 初見の人が説明なしで「次に何が起きるか」を言える。
3. **M3: 垂直スライス(K-01)** — ステージ3 を最終品質にし、全体の工数を見積もり直す。
4. **M4: 残りのステージへ展開と P2** — テーマ配色、ステージ選択、設定、BGM。
5. **M5: 試遊と調整(K-07、K-02)** — 5人の試遊とパフォーマンス計測で P3 を取捨選択する。
6. **M6: 提出整備(K-08)**

## 先に潰すリスク

1. **A-01 の補間**: `SnapToGrid` を補間に変えると、判定(グリッド座標)と見た目(ワールド座標)がずれる。判定は即時、見た目だけ補間にする。確認方法: 既存の解法入力列(`solutions.md`)が引き続きクリアできること。
2. **G-07 の日本語フォント**: サイズが大きいとリポジトリが重くなる。サブセット化して 2MB 以下にする。
3. **F-01 の音素材**: ライセンスが明確な CC0 だけを使い、出典を `specs/.../credits.md` に記録する。
4. **E-01 の斜めカメラ**: 箱で床が隠れて見えなくなる。E-05 で5ステージを確認する。
5. **D-01〜D-05 の Niagara**: ヘッドレス環境ではビジュアル確認できないため、通常のエディタで確認する。

## 確認方法

- 見た目: `unrealengine-cli pie screenshot` を各ステージで撮り、目視で確認する(通常のエディタ、`--headless` では 3D が写らない場合がある)。
- 動作: `play.py` 相当のスクリプトで、5ステージの解法が通ること(判定の退行がない)。
- 性能: `unrealengine-cli perf` で 60fps を確認する。
